# PoC – הוכחת היתכנות (משימה T-03)

אב-טיפוס מינימלי לבדיקת ההנחה הטכנולוגית המרכזית של FitVision AI: אפשר להריץ זיהוי שלד בדפדפן הטלפון, בקצב שמספיק למשוב בזמן אמת, ולספור חזרות בסקוואט בלי לשלוח וידאו לשרת. פירוט מלא בנספח ג' של מסמך האפיון.

## מה האב-טיפוס עושה

1. מפעיל את המצלמה הקדמית ברזולוציה של 640x480.
2. שולח כל פריים כ-`ImageBitmap` ל-Web Worker. בכל רגע נמצא ב-Worker פריים אחד לכל היותר.
3. ה-Worker מריץ את MediaPipe Pose Landmarker במצב `VIDEO` (`detectForVideo`), ומחזיר 33 נקודות ציון בתמונה ו-33 נקודות ציון בעולם (world landmarks).
4. ה-UI מחשב את זווית הברך מהנקודות התלת-ממדיות (ירך–ברך–קרסול, ממוצע של שתי הרגליים הנראות) ומחליק אותה בממוצע נע של 5 פריימים.
5. מכונת המצבים (איור 4.5: עמידה, ירידה, תחתית, עלייה) סופרת חזרות מלאות וחלקיות.
6. השלד מצויר על Canvas, ומוצגים FPS, השהיה חציונית ו-p95 וזמן ההסקה.
7. אם הקצב נמוך מ-15 FPS אחרי 3 שניות, המודל מוחלף אוטומטית מ-BlazePose Full ל-Lite (מענה לסיכון R-01).

## מבנה הקבצים

| קובץ | תפקיד |
| --- | --- |
| `index.html` | מסך יחיד: וידאו, Canvas, מונה חזרות ומדדים |
| `src/main.ts` | מצלמה, שליחת פריימים ל-Worker, חישוב זווית, ציור ומדידה |
| `src/pose.worker.ts` | טעינת MediaPipe והרצת `detectForVideo` מחוץ ל-UI thread |
| `src/messages.ts` | טיפוסי ההודעות בין ה-UI ל-Worker |
| `src/geometry.ts` | זווית מפרק משלוש נקודות, בדיקת visibility ≥ 0.5, ממוצע נע |
| `src/repCounter.ts` | מכונת המצבים לספירת חזרות; הספים מועברים כנתונים (TechniqueRules) |
| `src/metrics.ts` | FPS, אחוזוני השהיה וכלל המעבר ל-Lite |
| `src/repCounter.test.ts` | בדיקות יחידה ל-Vitest |

## הרצה

```bash
cd poc
npm install
npm test          # בדיקות יחידה (Vitest)
npm run dev       # שרת פיתוח; בטלפון יש לגשת בכתובת HTTPS כדי שהמצלמה תופעל
```

קובצי ה-WASM נטענים מ-jsDelivr ומודל ה-`.task` נטען מ-Google Storage, ולכן נדרש חיבור לאינטרנט בהפעלה הראשונה.

## סטטוס

- הלוגיקה הטהורה (זווית, ממוצע נע, מכונת מצבים ואחוזונים) נבדקה ב-8 בדיקות יחידה, וכולן עוברות.
- ההרצה בטלפון והמדידות (FPS והשהיה) יבוצעו בספרינט S4. התוצאות יירשמו בטבלה ג.2 בנספח ג'.
