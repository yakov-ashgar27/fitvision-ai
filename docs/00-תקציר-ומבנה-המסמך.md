### תקציר

מתאמנים רבים מתאמנים כיום ללא השגחה צמודה של איש מקצוע, בבית או בחדר כושר פתוח. כתוצאה מכך הם מבצעים תרגילים בטכניקה שגויה ללא משוב אובייקטיבי, ונחשפים לסיכון מוגבר לפציעות. במקביל, למאמני כושר אין דרך שיטתית לעקוב אחר ביצועי המתאמנים מרחוק, והם נאלצים להסתמך על דיווח עצמי סובייקטיבי.

הפרויקט מציע את FitVision AI: מערכת מידע מבוססת-ווב המשלבת מנוע ראייה ממוחשבת לניתוח תנועה בזמן אמת עם מערכת ניהולית למעקב ובקרה. המערכת מזהה את שלד המתאמן מתוך מצלמת הדפדפן באמצעות ספריית MediaPipe, מחשבת זוויות מפרקים, סופרת חזרות ומשווה כל חזרה לכללי טכניקה מוגדרים מראש. המתאמן מקבל משוב חזותי וקולי מיידי על שגיאות יציבה.

ליבת הפרויקט היא רכיב מערכות המידע. המערכת מנהלת שלושה סוגי משתמשים (מתאמן, מאמן ומנהל מערכת) במודל הרשאות מבוסס-תפקידים (RBAC), ומתעדת כל אימון ברמת הסט, החזרה ואירוע השגיאה. בסיום כל אימון מופק אוטומטית דוח סיכום אנליטי למאמן, הכולל כמות חזרות, ציון טכניקה, נקודות כשל חוזרות ומגמת שיפור ביחס לאימונים קודמים. המאמן יכול להוסיף הערות, לייצא את הדוח כקובץ PDF או Excel ולשלוח אותו למתאמן. כללי הטכניקה נשמרים כנתונים הניתנים לעריכה על ידי מנהל המערכת, ולא כקוד קשיח, כך שניתן להרחיב את מאגר התרגילים ללא פיתוח נוסף.

מטעמי פרטיות, הווידאו מעובד בצד הלקוח בלבד ואינו נשמר; לשרת מועברים נתונים מספריים בלבד. המערכת תפותח ב-React בצד הלקוח, Python (FastAPI) בצד השרת ו-SQL Server כמסד נתונים. תוצרי הניתוח כוללים דיאגרמת Use Case, דיאגרמות DFD ברמות 0 ו-1, דיאגרמת ERD ואפיון ממשקי משתמש. גרסת ה-MVP תתמוך בארבעה תרגילים: סקוואט, לאנג'ים, כפיפת מרפקים (Bicep Curl) ולחיצת כתפיים (Shoulder Press). התרגילים נבחרו כך שמצלמת טלפון אחת תזהה אותם באמינות: כולם מבוצעים בעמידה, כל הגוף נראה בפריים, והמפרק העיקרי נע בזווית רחבה ובמישור אחד מול המצלמה.

**מילות מפתח:** מערכות מידע, ראייה ממוחשבת, הערכת תנוחה (Pose Estimation), ניהול משתמשים והרשאות, הפקת דוחות, טכנולוגיית כושר

### Abstract

Many people train without professional supervision, performing exercises with poor technique and no objective feedback, which increases injury risk. Fitness trainers, in turn, lack a systematic way to monitor trainees remotely and rely on subjective self-reports.

FitVision AI is a web-based information system that combines real-time computer-vision movement analysis with a management layer for trainers. Using MediaPipe pose estimation in the browser, the system tracks joint angles, counts repetitions and checks each rep against configurable technique rules, giving the trainee immediate visual and audio feedback.

The core of the project is its information-system component: role-based access control for trainees, trainers and administrators; structured logging of every session at the set, repetition and error-event level; and an automatic reporting engine that produces an analytical post-workout report for the trainer, covering reps, technique score, recurring faults and progress over previous sessions. Trainers can annotate reports, export them as PDF or Excel, and send them to trainees. For privacy, video is processed client-side only and never stored. The system will be built with React, Python (FastAPI) and SQL Server.

**Keywords:** information systems, computer vision, pose estimation, role-based access control, automated reporting, fitness technology

## מבנה הפרקים של מסמך ההגשה – פרויקט סיום א'

המסמך בנוי מ-10 פרקים ונספחים, ומשבץ את ארבעת התרשימים שכבר הוכנו (Use Case, DFD, ERD, Wireframes) בפרקים 3–5. המבנה תואם את שלבי נוהל הפרויקטים של החוג: ייזום, תכנון וביצוע בגישה איטרטיבית מבוססת User Stories.

**עמודי פתיחה**

- עמוד שער: שם הפרויקט, שמות המגישים ות.ז., מנחה אקדמי, ארגון לקוח, תאריך הגשה
- תקציר בעברית ו-Abstract באנגלית (הטקסט שלמעלה)
- תוכן עניינים, רשימת איורים ורשימת טבלאות

1. **מבוא**
   1. רקע ותיאור התחום
   2. הגדרת הבעיה – שתי הבעיות: טכניקה לקויה ללא משוב, והיעדר מעקב שיטתי של המאמן
   3. מטרות הפרויקט – מטרה כללית ומטרות מדידות (למשל: דיוק ספירת חזרות של 95% לפחות)
   4. היקף ותיחום – מה בתוך ה-MVP (4 תרגילים, 3 סוגי משתמשים) ומה מחוצה לו
   5. הארגון הלקוח וקהל היעד – \[ארגון לקוח טרם נקבע; יושלם לאחר איתור חדר כושר או סטודיו\]
2. **סקירת מצב קיים ופתרונות קיימים**
   1. סקירת אפליקציות קיימות בשוק – טבלת השוואה לפי יכולות
   2. סקירה קצרה של טכנולוגיית הערכת תנוחה (Pose Estimation) ומחקרים רלוונטיים
   3. הפער שהפרויקט ממלא – הדגשת שכבת מערכת המידע (ניהול, לוגים, דוחות)
3. **ניתוח דרישות**
   1. בעלי עניין ושחקנים – מתאמן, מאמן, מנהל מערכת
   2. דרישות פונקציונליות כ-User Stories ממוספרות (US-01 ואילך) עם קריטריוני קבלה
   3. דרישות לא פונקציונליות – ביצועים (השהיית משוב, קצב פריימים), אבטחה, פרטיות, שימושיות, תאימות לדפדפנים
   4. **דיאגרמת Use Case** (FitVision\_UseCase.drawio) ותיאור מילולי ל-3–4 מקרי שימוש מרכזיים בטבלת תרחיש: שחקן, תנאי קדם, תרחיש ראשי, תרחישים חלופיים, תנאי סיום
4. **ניתוח ותכן המערכת**
   1. ארכיטקטורת המערכת – דיאגרמת רכיבים: דפדפן (React + MediaPipe), שרת (FastAPI), מסד נתונים, מחולל דוחות
   2. **דיאגרמות DFD** רמה 0 ורמה 1 (FitVision\_DFD.drawio) ומילון זרימות נתונים
   3. **דיאגרמת ERD** (FitVision\_ERD.drawio) ומילון נתונים לכל טבלה: שדה, טיפוס, אילוצים, תיאור
   4. כללים עסקיים – חישוב ציון טכניקה, הגדרת "מגמת שיפור", כללי ההתראות למאמן
   5. מודל הרשאות – מטריצת RBAC: תפקיד מול פעולה
   6. אלגוריתם ניתוח הטכניקה – חישוב זווית מפרק משלוש נקודות ציון, ומכונת מצבים לספירת חזרות
5. **אפיון ממשק המשתמש**
   1. מפת מסכים וניווט
   2. **Wireframes** (FitVision\_Wireframes.drawio) – מסך אימון חי, דשבורד מאמן, מסך דוח סיכום; מומלץ להוסיף גם מסך התחברות ופרופיל
   3. עקרונות עיצוב – תמיכה בעברית מימין לשמאל, נגישות, התאמה למובייל
6. **סביבת פיתוח וטכנולוגיות**
   1. רכיבי ה-Tech Stack ונימוק לכל בחירה (כולל ההחלטה על SQL Server והרצת MediaPipe בדפדפן)
   2. כלי ניהול ופיתוח – Git, מערכת ניהול משימות (Jira או GitHub Projects), סביבת בדיקות
7. **תוכנית עבודה וניהול הפרויקט**
   1. מתודולוגיה – Agile בספרינטים של שבועיים
   2. Product Backlog – פירוק ה-User Stories למשימות
   3. אבני דרך ולוח זמנים לשני הסמסטרים, כולל סקר האמצע בתחילת סמסטר ב'
   4. חלוקת תפקידים בצוות
8. **ניהול סיכונים** – טבלת סיכונים: תיאור, הסתברות, השפעה, דרך התמודדות. סיכונים מרכזיים: דיוק זיהוי בתאורה חלשה, ביצועים במכשירים חלשים, פרטיות מידע רגיש, הרחבת היקף
9. **תוכנית בדיקות והערכה**
   1. בדיקות יחידה ואינטגרציה
   2. בדיקת דיוק – השוואת ספירת המערכת לספירה ידנית על סרטונים מתויגים
   3. בדיקות שמישות עם מאמנים ומתאמנים
   4. מדדי הצלחה לפרויקט
10. **סטטוס בסוף סמסטר א' ותוכנית לסמסטר ב'** – מה הושלם (תכן, אב-טיפוס), מה נותר, ושינויים מהתכנון המקורי

## לבדוק מול הרכזים לפני ההגשה

לפי נוהל הפרויקטים של החוג (גרסה 3.0, 2018), הפרויקט נעשה מול ארגון לקוח – וזה הפער המשמעותי ביותר בהצעה הנוכחית. הנוהל מ-2018, ולכן כל הסעיפים כאן דורשים אימות מול הנחיות השנה.

- [ ] **ארגון לקוח:** טופס ההצעה דורש שם ארגון ופרטי איש קשר (שם, דוא"ל, טלפון). אפשרות טבעית: חדר כושר או סטודיו לאימון אישי שישמש כלקוח.
- [ ] **הרכב צוות:** צוות של 4 עומד בדרישת הנוהל (2–4 סטודנטים). להשלים את שמות כל חברי הצוות בטופס ההצעה ולפרט חלוקת תפקידים בפרק 7.
- [ ] **מועד הגשת ההצעה:** לפי הנוהל, עד סוף השבוע הראשון של סמסטר א', לאחר אישור המנחה.
- [ ] **פורמט התרשימים ומסמכי האפיון:** סוג ורמת הפירוט נקבעים על ידי הרכז באישור המנחה – לוודא שנדרשים DFD ו-ERD ולא, למשל, דיאגרמות מחלקה או רצף.
- [ ] **אורך התקציר:** הנוהל אינו מגדיר אורך; התקציר כאן כ-300 מילים בעברית.
- [ ] **משקלות הציון:** הצעת הפרויקט 10%, ניהול הפרויקט 20%, כנס הפרויקטים 20%, מימוש הפרויקט 50%.
