# מדריך הרצה וניסוי בטלפון

המדריך מסביר איך מריצים את FitVision AI ואיך מבצעים ניסוי אמת בטלפון נייד, כולל מילוי טבלה ג.2 (ביצועי MediaPipe במכשירים).

## 1. הרצה מלאה ב-Docker (מומלץ)

נדרשים Docker Desktop ו-8GB זיכרון פנוי לפחות, כי SQL Server צורך כ-2GB.

```bash
git clone https://github.com/yakov-ashgar27/fitvision-ai.git
cd fitvision-ai
cp .env.example .env          # לפני שימוש אמיתי יש להחליף את JWT_SECRET ואת הסיסמאות
docker compose up -d --build  # db (SQL Server 2022), redis, api, worker (RQ), web (nginx)
```

בהפעלה הראשונה השירות `api` יוצר את מסד הנתונים, מריץ את המיגרציה (Alembic) ומזין את נתוני הייחוס. האפליקציה זמינה בכתובת http://localhost:8080.

| משתמש | סיסמה | הערה |
| --- | --- | --- |
| admin@fitvision.app | Admin1234! | מנהל מערכת |
| trainer@fitvision.app | Demo1234! | מאמן, קוד הזמנה DEMO2028 |
| trainee@fitvision.app | Demo1234! | מתאמן עם 3 שבועות היסטוריה |
| avi@fitvision.app | Demo1234! | מתאמן שני, מייצר התראות |

משתמשי ההדגמה נוצרים רק כש-`SEED_DEMO=1`.

## 2. הרצה בתהליך אחד, בלי Docker

האפשרות מתאימה לפיתוח ולניסוי מהיר, ומשתמשת ב-SQLite במקום SQL Server.

```bash
# צד הלקוח
cd client
npm install
npm run build                 # מעתיק את MediaPipe ואת המודלים ל-public ובונה ל-dist

# צד השרת
cd ../server
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m playwright install chromium     # נדרש לייצוא PDF
export DATABASE_URL=sqlite:///./fitvision.db SEED_DEMO=1 STATIC_DIR=../client/dist
python -m alembic upgrade head && python -m app.seed
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

בלי Redis, השרת מחזיק את המטמון בזיכרון ומריץ את משימות הרקע (דוחות וייצוא) בתוך התהליך.

## 3. גישה מהטלפון

הדפדפן מאפשר גישה למצלמה רק בחיבור HTTPS (או ב-localhost). לכן לניסוי בטלפון צריך כתובת HTTPS. הדרך הפשוטה היא מנהרה זמנית:

```bash
# לאחר ש-docker compose רץ (פורט 8080), או uvicorn (פורט 8000)
cloudflared tunnel --url http://localhost:8080
```

הפקודה מדפיסה כתובת בסגנון `https://xxxx.trycloudflare.com`. פותחים אותה בטלפון ב-Chrome (אנדרואיד) או ב-Safari (iPhone). כדי להתקין כאפליקציה בוחרים "הוספה למסך הבית".

אם משתמשים בכתובת אחרת מזו שב-`CORS_ORIGINS`, אין צורך לשנות דבר: nginx מגיש את האפליקציה ואת ה-API מאותו מקור.

## 4. בדיקת המכשיר (דף /diag)

לפני האימון הראשון בכל מכשיר נכנסים ל-`/diag` (בהגדרות: "פתיחת בדיקת המכשיר"). הדף מפעיל את המצלמה הקדמית ואת MediaPipe ב-Web Worker, ומציג בזמן אמת:

1. המודל הפעיל (Lite או Full) ואם הוא רץ ב-GPU או ב-CPU.
2. FPS, והשהיה מהפריים ועד התוצאה (p50 ו-p95).
3. מספר נקודות הציון שזוהו (33 כשכל הגוף בפריים).

עומדים מול הטלפון כדקה, רושמים את הערכים, ואז עוברים למודל Full בכפתור ומודדים שוב.

את התוצאות מעתיקים לטבלה ג.2 (נספח ג'). הסף הנדרש: לפחות 15 FPS והשהיה p95 של עד 200ms (NFR-01, NFR-02).

## 6. הבדיקות האוטומטיות

הבדיקות רצות ב-GitHub Actions בכל push (`.github/workflows/ci.yml`), והתוצאות נשמרות בענף `ci-reports`.

| שלב | מה נבדק |
| --- | --- |
| server | ruff ו-pytest על SQLite, כולל הפקת PDF אמיתית ב-Chromium |
| server-mssql | SQL Server 2022 אמיתי: יצירת מסד, מיגרציה, בדיקת סכמה ו-pytest |
| client | eslint, ‏vitest (מנוע הטכניקה, סנכרון לא מקוון, רכיבים), ‏tsc ובנייה |
| e2e | Playwright במסך Pixel 7: אימון שלם עם הזנת נקודות ציון, מצב לא מקוון, לוח בקרת מאמן, ו-MediaPipe אמיתי על וידאו של אדם דרך מצלמה מדומה |
| stack | ‏docker compose מלא: התחברות דרך nginx, מטמון, ייצוא PDF ו-Excel דרך ה-worker, ו-Playwright מול המערכת המלאה |

הרצה מקומית:

```bash
cd server && pip install -r requirements-dev.txt && pytest -q
cd client && npm test && npm run e2e
```

## 7. מגבלות

- הבדיקות האוטומטיות מריצות את MediaPipe ב-Chromium בשרת, בלי GPU. ביצועים בטלפון אמיתי נמדדים רק בדף `/diag`, ולכן טבלה ג.2 ממולאת בניסוי ידני.
- ב-iPhone הדפדפן הוא Safari בכל מקרה. MediaPipe רץ שם ב-Web Worker עם WebGL; אם ה-GPU אינו זמין, המערכת עוברת ל-CPU ולמודל Lite.
- הספים בטבלה 4.6 הם ערכי פתיחה, ויכוילו מול מאמן מוסמך (T-04).
